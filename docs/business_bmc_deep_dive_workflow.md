# Business-Level BMC Deep Dive Workflow

会社全体のBMCは入口として使い、深掘りでは事業単位ごとに別のBMCを作る。ひとつの上場企業には、顧客、価値提案、収益構造、主要活動が異なる複数のビジネスモデルが混在しているため。

## 1. 事業候補を切り出す

起点は公式資料のセグメント、主要ブランド、主要プロダクト、地域別事業、販売チャネル。

切り出し条件:

- 顧客セグメントが異なる
- 価値提案が異なる
- 収益の流れが異なる
- 主要活動や主要リソースが異なる
- 競争環境やKPIが異なる

同じ条件に見えるものは無理に分けない。たとえば通信会社の個人通信と法人DXは分けるが、同じ顧客に同じ価値を売る料金プラン差は原則として分けない。

## 2. 優先順位を決める

各社ごとに、以下の順で深掘りする。

1. 売上・利益・投資額の大きい中核事業
2. 成長戦略上の重点事業
3. 他社比較で学習価値が高い事業
4. 会社全体BMCでは説明しきれない異質な事業

初回は各社3事業までを推奨する。網羅よりも、BMCの粒度と根拠水準を固めることを優先する。

## 3. 事業単位BMCを作る

自動生成された事業別BMCは、最初は `template_only` として扱う。これは画像枠と候補一覧を揃えるための初期案であり、公式資料で事業固有化するまで深掘り済みとはみなさない。

各事業で、9ブロックを会社全体ではなく対象事業の視点に限定して書く。

- 顧客セグメント: その事業が直接価値を届ける相手
- 価値提案: その事業固有の便益
- チャネル: その事業の販売・提供経路
- 顧客関係: 継続利用、保守、会員、法人営業など
- 収益の流れ: 売上、課金、手数料、保守、ライセンスなど
- 主要リソース: その事業固有の資産、技術、ブランド、データ、設備
- 主要活動: 開発、生産、調達、運用、営業、審査、保守など
- 主要パートナー: その事業の成立に必要な外部関係
- コスト構造: 原価、設備、人員、広告、調達、規制対応など

会社全体にしか言えない内容は書かない。判別できない場合は `要確認` に残す。

## 4. 根拠資料を厚くする

最低限の根拠:

- 有価証券報告書の事業等のリスク、経営方針、セグメント情報
- 決算説明資料のセグメント別売上・利益・KPI
- 統合報告書または中期経営計画
- 事業別ページ、サービスページ、製品ページ

公式資料にない推測は、画像化前に削るか `要確認` にする。

## 5. 会社全体BMCへ戻す

事業単位BMCを作った後、会社全体BMCを更新する。

- 会社全体BMCは「事業ポートフォリオを束ねるモデル」として整理する
- 事業単位BMCは「その事業がどう価値を作り、収益化するか」を整理する
- 同じ企業内で共通するリソース、顧客基盤、ブランド、データ、チャネルを横断資産として扱う

## Output

- 台帳: `data/business_bmc_backlog.csv`
- 事業別Markdown: `business_bmcs/{company_code}/{business_id}.md`
- テンプレート: `templates/business_bmc_template.md`

## Status Values

- `candidate`: セグメントから切り出した候補
- `scoping`: 事業境界を確認中
- `template_only`: 原型テンプレートから作った初期案。同じ原型の候補ではBMC本文が重複する
- `needs_research`: 公式資料で事業固有の顧客、価値提案、収益源を確認する必要がある
- `drafting`: 事業単位BMCを作成中
- `source_review`: 公式資料で確認中
- `ready_for_image`: 画像化可能
- `done`: 画像化とレビュー完了
